실제 사용 흐름

좋은 요청은 목적, 입력, 제약, 결과 형식을 짧게 포함합니다.

공통 기본 흐름

  1. 채널 선택
    일반 작업, 로컬 추론, 글쓰기, 영상 중 목적에 맞는 채널로 갑니다.
  2. 요청 입력
    세 전용 채널에서는 @태그 없이 작업을 바로 설명합니다.
  3. 인라인 응답 확인
    HQwen·Muse·Media는 전용 채널 본문에 진행 표시와 결과를 답합니다.
  4. 후속 요청
    같은 채널에서 수정 조건을 이어서 말합니다. 공유 채널에서는 원하는 봇을 @멘션합니다.

글쓰기·편집

아래 원고를 800자 이내의 행사 공지로 편집해줘. 독자는 처음 참가하는 개발자이고, 날짜·장소·신청 링크는 그대로 유지해줘.

#local-muse에서 원문, 독자, 톤, 분량, 반드시 유지할 요소를 알려주면 결과가 안정적입니다.

로컬 범용 추론

이 코드의 잠재적 버그를 찾고, 수정 전후 차이를 표로 보여줘. 기본 Q5 경로를 사용해줘.

#local-qwen에서 민감한 초안이나 반복 분석을 로컬로 처리합니다. 더 빠른 반복은 Q4, 품질 우선 검토는 Q6를 명시할 수 있습니다.

영상 생성

  1. 프롬프트 작성
    #video-gen에서 주제, 움직임, 카메라, 분위기, 화면비, 길이를 적습니다.
  2. 안전 확인
    Media가 모델·백엔드 상태와 매개변수를 검증합니다.
  3. GPU 작업 실행
    공유 잠금을 획득한 뒤 Wan 생성 작업을 직렬로 실행합니다.
  4. 결과 확인
    완료 파일과 조건을 #video-results에서 확인합니다.
새벽 안개가 흐르는 산 능선을 드론이 천천히 전진하는 영상. 16:9, 3초, 카메라 흔들림 없이, 사실적인 영화 톤으로 생성해줘.
상태만 확인하려면 “실제 영상을 생성하지 말고 dry-run으로 백엔드 상태만 알려줘”라고 명시하세요.

비교 실험

#model-arena에서는 같은 텍스트 프롬프트를 Hermes·HQwen·Muse 관점에서 비교하고, #video-arena에서는 모델·프롬프트·스텝·CFG 같은 영상 조건별 결과를 비교합니다.

기록할 것이유
동일한 원본 프롬프트비교 조건을 공정하게 유지
사용 모델·양자화속도와 품질 차이 해석
생성 시간실제 운영 비용 파악
최종 선택 이유다음 작업의 재사용 기준 확보

결과 관리

  • 전용 채널의 텍스트 결과는 같은 채널에서 인라인으로 후속 편집을 이어갑니다.
  • 최종 영상은 #video-results에 프롬프트와 함께 남깁니다.
  • 장애와 운영 상태는 #ai-ops, 상세 로그는 #ai-logs로 분리합니다.
